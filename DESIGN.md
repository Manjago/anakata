# anakata — дизайн

Черновик. Здесь зафиксировано «что» и «почему». «Как» — в коде и AGENTS.md.

## Идея

Однопользовательская текстовая игра для мессенджеров (сначала Telegram, потом Matrix). Игрок ходит по лабиринту и собирает буквы, из которых нужно составить слово. Назвал слово — телепортировался на следующий уровень.

Главная особенность: карта не рисуется, всё описывается только текстом. Поэтому лабиринт может быть не только двумерным, но и трёхмерным, и четырёхмерным. Название — от «ана» и «ката», направлений вдоль четвёртой оси (как «вверх» и «вниз» для третьей).

## Пространство и движение

- Лабиринт — N-мерная решётка, N = 2, 3, 4. Клетка задаётся координатами `int[N]`, у неё до 2N соседей.
- Направления:
  - 2D: север, юг, восток, запад;
  - 3D: плюс вверх, вниз;
  - 4D: плюс ана, ката.
- Игрок видит в клетке список доступных выходов и, иногда, что-то ещё (см. ниже). Координаты игроку не показываются.

## Комнаты и ориентиры

- Большинство комнат пустые. Примечательные (узор на стене, предмет, что-то ещё) встречаются редко, ориентировочно в каждой 5–10-й комнате. Если что-то есть в каждой комнате, ничего не запоминается.
- Ориентиры нужны для навигации, а не для красоты: в 4D это единственное, за что держится память игрока.
- Ориентиры генерируются детерминированно из сида и координат, отдельно не хранятся.
- Идея: сделать одну ось «ощутимой». Например, четвёртая координата меняет оттенок стен (в сторону ана — холоднее, в сторону ката — теплее). Это регулятор сложности: подсказку можно включать и выключать.

## Задание: буквы и слово

- На уровне разложены буквы загаданного слова. Буквы ставятся далеко от старта (по расстоянию BFS в лабиринте), а не за соседней дверью.
- Назвать слово можно в любой момент, даже не собрав всех букв.
- Если назвал, собрав не все буквы, и не угадал — cooldown до следующей попытки.
- Cooldown измеряется **в ходах**, а не во времени:
  - ядро не зависит от часов и остаётся детерминированным и тестируемым;
  - штраф превращается в исследование («иди поищи ещё»);
  - в асинхронном чате таймер в минутах ничего не значит.
- Засчитывается **любое слово из словаря**, составленное из тех же букв, а не только загаданное («кот» / «ток»). Значит, словарь должен уметь искать по мультимножеству букв, а не только проверять одно слово.
- Словарь — файл в ресурсах, слова отобраны вручную: «вилка» как ответ радует, «эпистемология» злит.
- Повторяющиеся буквы в принципе разрешены. Словарь — за интерфейсом, реализации под ним:
  - v1: только слова без повторяющихся букв, проверка по множеству букв;
  - v2 (позже): учёт кратностей, индекс по канонической подписи (отсортированные буквы), чтобы искать по мультимножеству.
  Усложнение словаря — это новая реализация того же интерфейса, ядро не меняется.

## Прогрессия

После телепортации — следующий уровень. Долгий горизонт: 2D → 3D → 4D, внутри измерения — рост размера и длины слова.

Сейчас прогрессия минимальная: при телепорте предлагается выбор из трёх опций — остаться на том же уровне, увеличить размер или увеличить измерение (размер при этом небольшой). Решение, как усложнять, — за интерфейсом.

Позже, вероятно, усложнение будет считаться хитрее — например, по метрикам поведения: если игрок «хорошо» проходит уровень, предлагать усложнение. Сегодня это не реализуется.

## Детерминизм и сид

- Уровень полностью определяется сидом и параметрами (размерность, размеры). Лабиринт, ориентиры и расстановка букв строятся из сида.
- Хранится только сид, параметры и состояние игрока, сам лабиринт не хранится.
- Уровнями можно делиться: «попробуй сид 42, 4D».
- RNG свой, ручной: у встроенных генераторов Java нельзя достать внутреннее состояние для сохранения.

## Архитектура

- **Ядро** — чистая логика без ввода-вывода: на вход типизированная команда игрока, на выход структура-ответ и новое состояние. Никакой сети, никаких часов.
- **Ввод и вывод ядра — это данные, а не строки и не JSON.** Ядро не знает про мессенджеры и про то, как ответ будет показан.
  - На вход — типизированная команда (направление, сказать слово, показать буквы, помощь и т.п.).
  - На выход — структура `Ответ`: описание комнаты, выходы, объекты, подсказка по 4D (если включена), состояние игрока (собранные буквы, cooldown), результат действия, доступные команды.
  - **Рендеринг целиком — задача адаптеров.** Адаптер сам решает, что показать и в каком виде: консоль рендерит в плоский текст, Telegram — текст плюс inline-кнопки (можно показывать только доступные команды), Matrix — свой рендер позже. Ядро не меняется.
  - Входящую команду тоже строит адаптер: консоль парсит строку, Telegram — нажатие кнопки.
- **Адаптеры** к ядру:
  1. консоль (stdin/stdout) — первый, чтобы играть в терминале и быстро проверять идеи;
  2. Telegram (long polling);
  3. Matrix — позже.
- **Сохранение** — H2 MVStore, состояние по пользователю мессенджера.
- **Модель сохранения — снапшот**, а не журнал команд. Хранится готовое состояние игрока: текущая клетка, собранные буквы (с кратностями), счётчик ошибочных попыток, оставшийся cooldown в ходах. Перемотки не будет: **необратимость хода — сознательная фишка**. Обратная совместимость баз не поддерживается, базу можно вайпнуть в любой момент.

## Технологии

- Java 25, Maven, без фреймворков, зависимостей минимум.
- Зависимости: логгер, H2 MVStore, Gson.
- **JSON нужен только для протокола адаптеров** (Telegram/Matrix), в ядре его нет. Выбор — **Gson**, а не Jackson: сравнение шло только между ними, задач на скорость databind или streaming в проекте нет, поэтому берём минимальный по зависимостям вариант. Gson живёт только в адаптерах.
- HTTP — встроенный `java.net.http.HttpClient`.
- На VPS — запуск через systemd.

## Генерация лабиринта: контракт

- Вход: сид, размерность N, размеры по осям. Выход: граф проходов на N-мерной решётке.
- Алгоритм — один из стандартных (бэктрекер, Прим, Крускал), за интерфейсом. Учесть, что алгоритм определяет характер лабиринта: бэктрекер даёт длинные извилистые коридоры, Прим — много коротких тупиков.
- Свойства, которые проверяются тестами:
  - все клетки достижимы из старта (BFS);
  - у идеального лабиринта число проходов ровно на 1 меньше числа клеток;
  - один и тот же сид — один и тот же лабиринт;
  - работает для N = 2, 3, 4.
- Возможно, понадобится параметр «петель»: идеальный лабиринт (дерево) в 4D может оказаться слишком жестоким. Проверить игрой.

## Открытые вопросы

- Алгоритм генерации по умолчанию и нужен ли параметр петель.
- Размеры уровней для каждой размерности.
- Плотность ориентиров и их виды (узоры, предметы, что ещё).
- Подсказка по четвёртой оси: какая именно, включена ли по умолчанию.
- Величина cooldown в ходах; растёт ли она с повторными ошибками.
- Конкретный набор команд игрока и набор полей структуры `Ответ` (направления, состав состояния игрока и т.п.).
- Алгоритм RNG (SplitMix64, xoshiro256** или другой).

8. Адаптер Telegram.
